# QDS6：连接导入导出与备份规范

> 日期：2026-11-10｜作者：lq｜版本：0.1｜状态：待实施规范。\
> 产品名：QDS6；正式格式标识与文件扩展名在 M0 格式设计时冻结。\
> 主方案：[产品与技术实施方案](./产品与技术实施方案-20261110.md)。

## 1. 首版范围

客户端仅支持 macOS 与 Windows；两端均可读取受支持的来源文件，不要求安装来源工具。客户端暂不支持 Linux 不影响连接 Linux 服务器、SFTP 服务，以及部署在 Linux 上的 MySQL/PostgreSQL。

实施顺序更新（2026-11-10，lq）：先完成 Mac 的解析、预览、导出和备份恢复基本链路；Mac 主要功能落地后再开展 Windows 适配及双向恢复。下文两端验收要求保留为最终目标，不阻塞当前 Mac 阶段推进。

首版必须实现参考工具导出的连接文件导入，并实现本工具连接配置导出、手动备份与恢复。数据库内容和远程文件内容不属于应用配置备份；远程编辑草稿属于可选客户端数据。

兼容性以“来源工具 + 版本 + 导出方式 + 文件格式 + 可迁移字段”为单位记录。样例未覆盖的格式不宣称已支持；不支持的条目在预览中说明，不将整个导入需求延后为后续版本。

## 2. 来源适配矩阵

| 来源 | 首版输入目标 | 导入对象 | 主要边界与验证要求 |
| --- | --- | --- | --- |
| PuTTY | 用户导出的 Sessions 注册表 `.reg` 文件 | SSH 会话 | 仅读取受支持会话键；解析 UTF-16/转义/会话名编码。非 SSH 会话跳过并报告；不执行 `.reg`，不修改注册表 |
| FinalShell | 连接管理器可导出/备份的文件；连接配置目录/JSON 作为候选兼容入口 | SSH 连接与分组 | 先取得来源版本的真实脱敏样例，确认容器、目录与字段；目前不将网上出现的 `conn.json` 等名称认定为统一官方导出标准 |
| FileZilla | File → Export 导出的站点管理 XML | SFTP 站点与目录分组 | 按实际协议标识区分 SFTP 与 FTP/FTPS；首版只导入 SFTP，不把 FTP 端口改为 SSH |
| Navicat 17 | File → Export Connections 导出的 `.ncx` | MySQL/PostgreSQL 连接与相关隧道设置 | 按源版本验证结构与编码；其他数据库类型跳过并报告，保留可映射的分组和连接关系 |
| 本工具 | 本工具连接配置或应用备份 | SSH/SFTP/MySQL/Pg、分组及关联配置 | 根据格式版本迁移，跨 macOS/Windows 恢复，并保留隧道引用关系 |

PuTTY 的 `.reg` 由用户通过系统导出会话配置获得，不描述为 PuTTY 内置的通用导出按钮。公钥认证可能引用外部 `.ppk`，导入路径不等同于导入密钥本体；后端不支持的密钥格式须提示重新选择或显式转换。

FinalShell 的标准导出、备份与配置目录兼容分别验收，不能仅支持内部配置文件便宣传已支持所有导出格式。没有用户真实样例前，先用受控测试连接生成脱敏样例，不读取用户本机已有工具的实际配置或密码。

## 3. 统一中间模型

适配器只解析为中间数据，不直接连接网络、修改系统配置或写入正式连接库。

| 字段组 | 归一化内容 | 不完整时的处理 |
| --- | --- | --- |
| 来源 | 工具、版本、格式、来源内标识、文件校验信息 | 未知版本明确标记，不能猜测成功 |
| 基础信息 | 显示名、分组、协议、主机、端口、用户名、备注 | 主机或协议缺失时不创建可连接条目 |
| SSH | 认证类型、密钥引用、受支持 Agent/跳板设置 | 密钥或跳板缺失标为待补全 |
| SFTP | 初始远端目录、本地目录、SSH 关联 | 本地目录不存在时保留原始路径供重映射，不自动创建任意来源路径 |
| 数据库 | MySQL/Pg 类型、地址、端口、用户名、默认库和受支持参数 | 数据库类型不支持则跳过，字段丢失在预览中列出 |
| 隧道 | SSH 服务器、端口、用户、认证引用、目标地址 | 不能映射时禁止静默改为数据库直连 |
| TLS | 加密模式、证书验证、CA/客户端证书引用 | 不支持的模式要求确认适配；不能为连通而静默关闭校验 |
| 凭据 | 待迁移秘密或 CredentialRequired 状态 | 不能读取的密文不可作为密码使用；提示用户补充 |
| 兼容报告 | 已映射、转换、忽略、待补全、阻断项 | 逐连接展示，不只显示总数 |

来源可能包含代理命令、登录后自动命令、外部脚本和任意附加选项。首版不执行这些内容，保留为不可执行的来源说明或报告为未支持。

导入的已信任主机信息不自动等同于本工具已核实身份；首版仍按本工具的主机指纹策略确认。

## 4. 导入交互与一致性

1. 用户选择来源与文件，按内容和来源校验格式，不只依据扩展名。
2. 限制文件大小、条目数、嵌套深度与解析时间；XML 禁止外部实体和外部资源加载。
3. 显示解析结果与原分组，默认只选中有效、支持的连接；待补全条目可选择导入为禁用草稿。
4. 检查重复项。优先使用本工具稳定 ID 或已记录的来源 ID，地址等字段相同只作为疑似重复提示。
5. 用户为重复项选择跳过、替换或保留两份；名称相同但环境不同不能自动覆盖。
6. 预览密钥、证书、本地路径与隧道引用的映射；提供批量重定位，不擅自打开来源引用的文件。
7. 用户确认后才写入。取消预览不改变配置，不创建可用凭据，也不发起连接。
8. 正式写入前建立本地恢复点，生成目标 ID 与引用映射；使用数据库事务提交配置。
9. 系统凭据库和 SQLite 无法共享同一数据库事务：先用暂存 ID 保存新凭据，配置提交成功后启用；失败清理暂存，不覆盖或删除旧凭据。
10. 为中断恢复记录操作日志；重启时完成或回退未完成的迁移，旧配置仍可用。
11. 输出成功、禁用待补全、跳过、失败数量及字段报告；日志不得包含密码、密钥内容或原始完整源文件。

未支持的密码加密不阻止读取可迁移的非秘密配置，但必须准确标记“密码需重新输入”，不能显示为全部迁移成功。

## 5. 源工具凭据处理

- 只处理用户主动选择的导出文件和明确选择的外部资源，不扫描系统中其他工具的凭据。
- 明文或可直接解码字段在导入时转换为本工具凭据引用；编码不等于加密，不把原字段长期复制到配置表。
- 来源采用主密码保护且存在已验证的兼容读取方式时，由用户输入主密码再迁移，主密码不持久保存。
- 来源采用尚未兼容的保护方式或依赖机器绑定信息时，提示重新输入密码或选择密钥，保留其他字段。
- 首版不以支持源工具所有历史密码算法为退出条件，但每个已支持版本必须明确声明凭据迁移级别。
- 不提供破解口令功能，不将外部密码恢复程序作为隐式导入步骤。

## 6. 本工具导出模式

| 模式 | 默认范围 | 秘密与用途 |
| --- | --- | --- |
| 导出选中连接 | 选中连接、必要分组、关联隧道和非秘密选项 | 默认不含密码/口令/密钥本体；用于共享配置和快速迁移 |
| 完整设置备份 | 所有连接、分组、偏好与布局 | 默认不含凭据；用户可以选择加密凭据、密钥及其他内容 |
| 自定义备份 | 用户选择的连接、设置、保存 SQL、历史与草稿 | 页面准确显示范围；历史、草稿和私钥默认不选 |

导出连接时附带依赖清单，不能遗漏该连接所需隧道。无凭据文件仍可能含服务器地址、用户名等内部信息，界面描述为“不含凭据”，不称为“无敏感信息”。

本工具原生格式保证可往返恢复。首版不要求反向生成 Navicat、FinalShell、PuTTY 或 FileZilla 格式，避免对未实现的双向兼容作出承诺。

## 7. 备份结构与加密

- 文件采用可版本化容器，使用稳定格式标识、schema_version、应用版本、创建时间和来源平台。
- 容器保存连接、分组和依赖的稳定 ID；资源使用容器相对标识，不以绝对路径作为唯一关联。
- 记录内容范围、条目数、资源类型与长度，必要信息有完整性保护；校验和不能替代加密认证。
- 用户选择包含任何秘密时，整体敏感负载使用口令派生密钥和成熟 AEAD 算法加密。M0 从受维护库中确定 Argon2id + AEAD 的实现和参数，不自研密码算法。
- 使用随机盐和满足所选算法要求的唯一 nonce；在头部记录派生参数和格式版本，并对相关元数据进行认证。
- 导入时对 KDF 参数、容器体积和解压后大小设置上限，避免恶意文件耗尽 CPU/内存。
- 口令不写入文件、日志、SQLite 或默认诊断报告；恢复不依赖原机器凭据库，不能直接导出系统凭据数据库。
- 私钥仅在用户明确选中具体密钥时包含；Agent 中不可导出的密钥保持引用并提示重新绑定。
- 备份写入采用临时文件及完成后的替换策略，失败不覆盖已有有效备份。
- 原生格式扩展名和格式标识以 qds6 为命名前缀，在 M0 格式设计时冻结，不因后续显示名变化随意更改。

## 8. 恢复与跨平台迁移

恢复先校验容器、口令、完整性、版本与所有资源，再展示连接、配置和凭据范围。未知新版格式应拒绝或转为明确的只读检查，不猜测导入。

用户选择合并或替换后，先创建恢复前快照。替换只影响用户选择的客户端范围，不删除远端文件或数据库内容，不触发 SQL、终端命令或自动连接。

新凭据使用暂存 ID 重建到目标系统凭据库，连接通过稳定 ID 重映射。路径在跨平台时提示重定位；系统特有 Agent 或凭据能力不可用时标记待补全，不能默认为另一种认证方式。

布局可以恢复，但会话显示为断开；查询历史与草稿默认不恢复为执行中的任务。凭据库写入失败、磁盘满或恢复中断时保留原配置，并通过迁移日志恢复一致性。

归档内容禁止绝对路径、父目录穿越、越界符号链接与重复路径覆盖；外部资源解压至私有暂存区，验收成功后再纳入应用资源目录。

## 9. 首版验收矩阵

| 场景 | 必须验证的结果 |
| --- | --- |
| 四类来源样例 | 每类至少一个明确版本的真实受控导出样例，包含分组、中文名、默认/非默认端口 |
| PuTTY .reg | macOS/Windows 都能解析 SSH 会话，不执行注册表操作，外部密钥路径待补全 |
| FinalShell | 根据实际导出/备份样例分别验证容器与连接目录，不凭 JSON 文件名宣称兼容 |
| FileZilla XML | 只迁移 SFTP；FTP/FTPS 不被误识别；密码保护无法兼容时有准确提示 |
| Navicat 17 .ncx | MySQL/Pg 分别验证，含 TLS、SSH 隧道和外部证书；其他类型跳过并报告 |
| 重复导入 | 来源 ID 与稳定 ID 策略正确，用户可跳过/替换/保留，取消不写入 |
| 缺失凭据或文件 | 标记为待补全，连接字段保留，不能静默降级认证、隧道或 TLS |
| 原生导出往返 | 分组、连接、隧道和可选资源一致，导出不遗漏所需依赖 |
| 加密备份 | 错误口令、截断、篡改、超大 KDF 参数均失败且不破坏当前配置 |
| 跨平台恢复 | macOS → Windows、Windows → macOS 均可恢复，并实际连接 SSH/SFTP/MySQL/Pg |
| 恢复中断 | 配置事务与凭据暂存可恢复，旧配置不因半成品写入失效 |
| 恶意文件 | XML 外部实体、路径穿越、压缩炸弹、异常字段和过量条目被限制 |
