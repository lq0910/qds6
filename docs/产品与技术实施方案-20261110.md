产品核心是围绕连接上下文完成工作：连接服务器后打开终端、浏览文件、修改配置，再通过 SSH 隧道访问数据库。界面保持统一，网络任务可以独立取消、重试和恢复。

## 4. 首版功能范围

### 4.1 连接与工作区

- 按项目或环境分组，保存服务器和数据库连接，支持收藏、搜索与最近使用。
- 密码、密钥口令与配置分开存储；配置导出默认不包含秘密。
- 连接管理提供“从其他工具导入”“导出连接”和“备份与恢复”入口，导入先预览再写入。
- 标签页可关闭、拖动和分屏，保存窗口布局与连接引用。
- 恢复布局时显示断开状态，不自动重放命令、SQL 或未完成的写操作。
- 提供浅色、深色主题及字体设置，生产环境连接使用持续可见的标记。

### 4.2 SSH 终端

- 密码、常用私钥认证，以及经验证的平台 SSH Agent 接入。
- 正确显示主机指纹；首次连接确认，主机密钥变化时阻止静默接受。
- 支持会话标签、分屏、复制粘贴、搜索、字体缩放和有限回滚缓冲。
- 支持保活、超时和断线提示；重新连接由用户发起，不重放旧命令。
- 首期实现单跳跳板机及本地端口转发，供数据库隧道复用。
- 验证 xterm-256color、Vim、tmux、top、中文、宽字符与括号粘贴行为。
- 首期不提供广播输入、复杂多跳和批量脚本执行。

### 4.3 SFTP 文件管理

- 本地/远程双栏浏览，远程目录支持排序、搜索、面包屑、隐藏文件和刷新。
- 上传、下载、创建目录、重命名、删除，以及权限查看与基础修改。
- 队列展示传输状态、进度、速率、失败原因；支持取消和受控重试。
- 首期默认最多 3 个并发文件传输，允许在设置中调整并设上限。
- 同名覆盖、目录合并和符号链接分别定义行为；不默认跟随符号链接递归。
- 文件续传在来源与目标校验通过时启用；无法确认一致性时重新传输。
- 文件名、路径与非 UTF-8 情况必须显式处理，不能静默乱码或修改路径。
- 双击受支持文本文件进入内置编辑标签；二进制和超限文件提供下载操作。

### 4.4 轻量远程文件编辑

**唯一编辑组件选择：GPUI Kit。** 禁止为该功能引入 Zed editor crate、Monaco 或独立 WebView。

首期提供语法高亮、行号、查找替换、撤销重做、缩进、换行符提示、未保存标记与保存。首轮只启用配置文件和脚本所需的少量语法，如 JSON、YAML、TOML、INI、Shell、SQL 与 XML；具体可用语法以锁定版本验证结果为准。

编辑器初始策略为 5 MiB 可编辑上限，同时限制行数和单行长度；阈值在 M0 压测后调整。大日志和二进制文件下载到本地处理，不将全文无限制载入编辑器。

远程保存流程必须实现：

1. 打开时读取远程属性和内容，创建基线及本地编辑缓存。
2. 编辑过程中保存本地草稿，网络断开不丢失已输入内容。
3. 保存前重新读取远程属性；属性有变化时重新读取内容比较。元数据精度不足时增加内容比较，不能将 mtime 当作强版本号。
4. 检测到远端变化时展示冲突，允许比较、另存为或用户明确覆盖。
5. 上传到同目录临时文件，检查写入结果、权限和必要属性，再选择服务器支持的重命名方式替换。
6. 仅在服务器支持并验证相应能力时声明原子替换；属性检查与替换之间仍可能发生竞争，不声称存在通用 compare-and-swap 保证。
7. 不支持安全替换、遇到符号链接或无法保留必要属性时明确反馈，保留本地草稿，不静默改变链接语义或退化为截断原文件。
8. 保存成功后更新基线；失败不清除未保存标记。

草稿与缓存保存在应用私有目录，限制访问权限，提供清理策略；持久草稿加密密钥存放于系统凭据库。凭据库不可用时回退到会话内草稿并告知用户，不以明文长期保存敏感配置。

### 4.5 MySQL / PostgreSQL

- 直连、TLS 与 SSH 隧道连接；数据库 TLS 默认校验服务端证书。
- 数据库对象树、表结构、索引和视图的基础查看。
- SQL 查询标签、执行选中语句/当前语句、结果集、耗时、错误定位与执行历史。
- 基础表数据浏览、过滤、排序、单元格编辑、插入与删除，以及 CSV 导出。
- 数据修改先形成待提交变更，提交前展示实际操作与影响范围。
- 仅对可可靠定位的基础表启用网格写入；没有可靠唯一键的表和任意查询结果默认只读。
- 正确区分 NULL、空字符串、精确小数、超大整数、时区和二进制值。
- 用户值使用参数绑定，数据库对象标识符通过对应方言引用，不能使用参数绑定代替标识符处理。
- 手动事务绑定专用连接；断连或取消后不能把状态未知的连接直接放回池中。
- 分库实现查询取消；取消操作使用独立控制连接或协议能力，不只取消本地 future。
- 基础建表与字段修改通过表单生成 DDL 预览；分别处理两种数据库的事务和锁行为。
- 不自动为任意 SQL 拼接 LIMIT 或 COUNT；查询浏览使用受控生成语句，用户 SQL 通过流式读取和明确的结果上限控制。

首轮验证基线为 MySQL 8.4 与 PostgreSQL 17；MySQL 8.0、PostgreSQL 16 等版本在兼容性测试后列入正式支持矩阵，不提前承诺全部版本兼容。

首版不做数据同步、结构对比、全库迁移、ER 建模、可视化查询生成器和高级备份调度。CSV 导入作为 0.2 候选，需单独处理字段映射、编码和事务策略。

### 4.6 连接导入、导出与备份恢复

首版支持从 PuTTY 会话导出的 `.reg`、FinalShell 连接配置文件/目录或其受支持备份、FileZilla 站点导出 XML，以及 Navicat 17 连接导出 `.ncx` 迁移连接；导入范围限 SSH/SFTP 与 MySQL/PostgreSQL。具体版本和字段必须经样例验收，不将“能读部分字段”标成完整兼容。

导入保留可映射的连接名、分组、地址、端口、用户名、数据库、SSH 隧道和 TLS 配置。密码、私钥、证书及外部文件依源格式能力处理，不能迁移时逐项提示补充。支持在任一首版平台读取这些文件，PuTTY `.reg` 不要求 Windows 注册表运行环境。

统一流程：选择来源与文件 → 解析与兼容报告 → 连接/分组预览 → 重复项处理 → 确认导入 → 成功/跳过/失败报告。导入不会自动连接服务器、执行来源脚本或写入系统注册表。

导出提供两种用途：可移植连接配置（默认不含凭据）与应用设置/连接的手动备份。含密码、口令或所选私钥的备份必须使用用户口令加密，不能直接复制本机凭据库记录充当可移植秘密。

备份默认覆盖连接、分组、隧道、偏好和布局；查询历史、保存的 SQL 与远程编辑草稿由用户选择。此功能备份客户端配置，不等同于 MySQL/Pg 数据库备份或 SFTP 远程文件备份。

恢复前展示内容、版本与缺失资源，支持合并或替换，先建立可恢复快照；失败不留下部分配置。首版要求 macOS 与 Windows 之间完成配置及可选凭据的往返恢复。

格式映射、凭据边界、备份结构与验收详见[连接导入导出与备份规范](./连接导入导出与备份规范-20261110.md)。

### 5.2 视觉原则

- 专业、克制、高信息密度；以字体层次、留白、对齐与选中状态建立秩序。
- 使用语义化主题色和统一组件尺寸，字体、行高、边框、间距集中配置。

- 动效用于反馈和过渡，不以持续动画保持渲染循环。
- 首轮基准在 1440×900 窗口检查，兼顾缩小窗口、125%/150%/200% 缩放和多显示器。

### 5.3 快捷键与输入

- 适配平台的 Command/Control 习惯，菜单中展示实际快捷键。
- 终端、SQL、远程编辑器分别管理焦点和快捷键；终端 Ctrl+C 保持终端语义。
- 提供全局快速连接和命令面板，输入框、菜单、对话框具备可见焦点。
- 输入法组合输入期间不截断文本、不触发意外提交；检查中文、emoji 和组合字符。
- 断线、空目录、加载、取消、失败和只读状态均有明确反馈。

## 6. 技术架构

### 6.1 分层与组件状态

| 层 | 技术/模块 | 状态与边界 |
| --- | --- | --- |
| UI | GPUI Kit、匹配的 GPUI、Kit 编辑组件 | 已确定；精确版本在 M0 锁定 |
| 应用服务 | 连接、会话、任务、工作区、远程编辑协调器 | 自研 Rust 模块 |
| 迁移与备份 | ImportAdapter、ImportPlan、BackupService | 来源解析、统一映射、预览、校验与事务恢复；与 UI 和网络任务分离 |
| SSH | russh | 候选；需验证认证、Agent、跳板机与平台兼容 |
| SFTP | russh-sftp | 候选；需验证服务端扩展、续传与重命名行为 |
| 终端 | alacritty_terminal + GPUI 适配 | 候选；状态机与绘制层分开，不等同完整终端控件 |
| 数据库 | SQLx 的 MySQL/Pg 具体驱动 | 候选；确认运行时类型、TLS、连接与取消能力 |
| 异步 | Tokio + 有界任务通信 | 候选；与 GPUI 事件循环集成在 M0 验证 |
| 本地数据 | SQLite | 保存非秘密配置、布局、必要历史；访问移出 UI 线程 |
| 凭据 | 系统凭据库抽象 | 首版验证 macOS Keychain、Windows Credential Manager；Linux 实现延后 |
| 打包 | cargo-packager 或各平台工具 | 候选；验证实际安装、签名与离线依赖 |

GPUI Kit 的许可与组件可用性依锁定版本检查，不依据 README 的组件数量推断特定接口已经可用。终端状态机、SQLx 和其他候选组件的精确版本与许可纳入 M0 清单。

GPUI Fast 仅作为默认后端存在明确瓶颈后的可选实验；GPUI-CE、GPUiX、GPUI Native、IncaJS 和 GPUI Shell 不进入首版依赖。以后需要脚本插件时另立方案。

### 6.2 核心对象与所有权

| 对象 | 职责 |
| --- | --- |
| ConnectionProfile | 连接配置，引用 CredentialRef、跳板机或隧道配置，不直接持有持久密码 |
| SshSession | 管理认证与底层连接、通道、保活、断连原因及引用计数 |
| TerminalSession | 管理终端状态、PTY 尺寸、输入输出、回滚上限 |
| TransferJob | 管理文件传输状态、进度、重试与取消 |
| RemoteDocument | 管理远端路径、原始编码、基线、草稿和保存状态 |
| TunnelLease | 管理隧道使用者与本地监听端口，默认仅绑定回环地址 |
| DatabaseSession | 管理数据库类型、查询与事务连接、隧道租约及结果流 |
| Workspace | 保存标签、分屏布局与连接引用，不保存可自动执行的指令 |
| ImportPlan | 保存来源、映射、重复项策略、待补字段和写入预览，不直接触发网络连接 |
| BackupManifest | 标识格式版本、应用版本、内容范围与校验关系，不包含明文秘密 |

SSH 的终端、SFTP 与隧道可以在条件允许时共享连接，但大文件传输可能影响同一连接上的交互流。默认限制并发，压测存在干扰时使用单独传输连接。关闭终端标签不能误关仍被数据库使用的隧道。

### 6.3 数据与线程边界

- GPUI UI 线程只进行交互、状态更新与有限的绘制准备，不执行同步网络操作。
- 网络读取、文件 I/O、语法解析和大结果转换在合适的后台任务中执行。
- 终端输出先更新原生状态机，按批次通知绘制，不按字节重建界面。
- 表格与目录使用虚拟显示，查询使用有界批次；虚拟列表不能替代数据源内存限制。
- 所有长任务具备取消、超时、所有者与明确的最终状态；结果晚到时不得更新已销毁标签。
- 设置连接数、结果缓存、回滚行数和传输队列上限；禁止无限制启动任务。
- 分页结果没有稳定排序时不承诺浏览一致性；实时变化的数据明确说明刷新语义。

## 7. 性能与轻量化验收

以下数字是首轮工程目标，不是已经达到的结果。M0 测量后记录基线；任何调整必须保留原因和对比数据。

| 指标 | 首轮目标 | 测量口径 |
| --- | --- | --- |
| 启动至可交互 | 冷启动 ≤ 3 秒，暖启动 ≤ 1.5 秒 | 不包含联网连接耗时，每端至少 10 次，报告中位数和 P95 |
| 空闲 CPU | 稳定后平均 ≤ 单核 1% | 断开连接，停止输入，观察 60 秒；记录显示器刷新率 |
| 基础窗口内存 | CPU 侧进程内存 ≤ 250 MiB 为优化目标 | 显示 1440×900 主界面，无连接；按平台报告原生内存指标和独立 GPU 占用 |
| UI 响应 | 压测时输入/交互到呈现 P95 ≤ 50 ms | 终端持续输出并传输文件时测量，标明负载 |
| 表格滚动 | 60 Hz 显示器下接近刷新率，主要帧时 P95 ≤ 20 ms | 使用固定字段宽度和数据集，记录长帧与缓存上限 |
| 单架构下载包 | ≤ 60 MiB 为优化目标 | 包含实际运行必需的内置资源；单列签名与容器开销 |
| 安装体积 | ≤ 120 MiB 为优化目标 | 明确是否包含外部运行时或系统依赖，不能只报主可执行文件 |

首轮参考机器：Apple Silicon 16 GB macOS；主流四核以上、16 GB、集成显卡 Windows。Linux 不进入首版性能验收。实际型号、OS、驱动、分辨率、缩放、提交号与构建参数必须记入报告，不直接跨平台比较口径不同的内存值。

压测包括 10 个终端、单终端约 1 MiB/s 输出、1 GiB 文件传输、万级文件目录、十万行×二十列测试数据。分别测试单项和组合负载；十万行是测试数据源规模，不要求全量常驻内存。

轻量化措施：按组件启用 Cargo features；只嵌入必要语法与图标；不携带 Zed、浏览器运行时或语言服务全家桶；使用 release 优化、符号分离与单架构发布。基于性能剖析选择优化，不能仅追求主程序文件更小。

## 8. 跨平台与发布要求

**开发顺序（2026-11-10 用户确认）：先按计划推进 Mac，Mac 版功能基本落地后再开发 Windows。** 当前开发、CI 和 M0–M3 退出判断均以 macOS 为先；Windows 编译、凭据库、Agent、窗口输入、性能及安装待办延期，不因未执行 Windows 验收阻塞 Mac 阶段推进。保留必要的平台接口，不提前开展 Windows 专属功能。

Windows 启动门槛：Mac 的连接与凭据、SSH 终端、SFTP 传输/编辑、MySQL/Pg 查询、四类连接导入及本工具导出/备份恢复已有基本可用链路与分项验证记录，M0 关键阻断已处理。到达门槛后启动 W0 适配，复用 Mac 已实现能力，并补齐 Windows 平台差异及两端迁移验收。Mac 发布候选检查按 Mac 证据独立进行，Windows 支持声明以其自身验收为准。

- macOS：首轮 Apple Silicon，随后验证 Intel；签名、公证、权限和升级流程独立验收。
- Windows：首轮 x64；验证缩放、窗口焦点、Agent、凭据库、路径与安装卸载。
- Linux：首版暂不支持，不提供安装包，不计入构建、性能与发布验收；保留平台抽象，未来扩展时再验证 Wayland/X11、依赖与凭据服务。
- 最终声明“两端支持”必须各有真实运行证据，单纯编译通过或截图展示不能替代；这不是 Mac 阶段推进的前置条件。
- 签名凭据尚未配置时可交付内部测试构建，但不能标为正式可分发版本。
- 首版允许手动下载安装升级；自动更新后续启用，必须验证签名、安装失败恢复和数据迁移。
- 配置数据包含 schema_version 和迁移记录；升级前备份，不能让降级静默破坏数据。

## 9. 开发阶段与退出条件

不把未经验证的阶段直接换算为固定交付日期，M0 完成后再按实际工作量排期。

| 阶段 | 内容 | 退出条件 |
| --- | --- | --- |
| M0 技术验证（Mac） | Mac 窗口、布局、Kit 编辑器、表格、终端链路、数据库、导入样例与备份原型 | Mac 核心链路可运行，组件精确版本/许可/包体/内存有记录；阻断问题有处理决策 |
| M1 连接与终端（Mac） | 工作区、凭据、认证、终端、跳板/隧道，SSH/SFTP 配置导入与导出备份 | Mac 完成连接和终端交互，SSH/SFTP 来源导入、去重、备份与恢复通过 |
| M2 SFTP 与编辑 | 双栏浏览、队列、传输、远程文件编辑与冲突处理 | 上传下载可核对内容，断线保留草稿，远端冲突与安全替换路径有实证 |
| M3 数据库 | 两种数据库的对象树、查询、网格、事务、取消、基础 DDL 与 Navicat 导入 | 两种数据库完成直连/隧道；Navicat 映射和本工具备份往返恢复通过 |

| W0 Windows 适配（Mac 主要功能落地后） | Windows 构建、窗口、凭据/Agent、路径、输入、服务、性能、安装及跨平台恢复 | 分项完成 Windows 运行与安装证据后，才声明 Windows 支持 |

M2、M3 同样先在 Mac 实施和验收。W0 复用原任务清单中的 Windows 与跨平台验收项，不将延期项删除或提前勾选。

## 10. 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| Kit 版本变化、GPUI 类型不兼容 | 使用配套版本与 Cargo.lock，不拼接多个 GPUI 来源；升级单独验证 |
| 编辑组件与终端中文输入、焦点问题 | 放在 M0，用真实输入法与两端窗口测试，不只依赖模拟按键 |
| 终端开发成本超过预期 | 复用状态机，先覆盖明确协议与常见程序；不以普通文本输出冒充终端 |
| SFTP 替换和元数据支持差异 | 按服务器能力选择策略，失败保留草稿，不承诺通用原子写入 |
| 数据库方言、取消和事务差异 | 分库适配，保留专用事务连接，分别设计取消和恢复路径 |
| 来源格式和密码保护机制变化 | 按工具版本与样例建立适配矩阵；缺失字段和不支持的凭据显式提示 |
| 备份跨平台后路径、凭据或引用失效 | 使用可移植标识，恢复时重建凭据并重映射资源；未补全连接不自动启用 |
| 安装包或内存超目标 | 使用实际功能构建剖析，标明必需依赖，不引用空白示例作为产品结果 |
| 修改参考产品后仍背负过大维护成本 | 独立核心、少量稳定依赖；首期不 fork Zed、不自建 GPUI 分支 |
