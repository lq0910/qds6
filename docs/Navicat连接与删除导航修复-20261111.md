# Navicat 连接与删除导航修复

日期：2026-11-11；作者：lq。

## 修复

- 导入器此前忽略源文件明确的 `SSL=false`，强制使用严格 TLS。现在对明确关闭的设置保持一致；开关缺失仍保留严格 TLS，未知或未映射的已启用 SSH/TLS 设置继续阻断，不在连接失败后自动降级。
- 真实 NCX 的 PostgreSQL 库名使用 `Database` 属性，此前仅读取 `InitialDatabase`。现在优先读取 `Database` 并兼容旧字段。
- 重新导入时精确匹配旧算法生成、遗漏数据库名的连接 ID，将配置和临时密码关联到原连接；通过原有确认、快照和事务合并更新。连续重新导入保持幂等，不误匹配手动新建或身份字段已改动的连接。
- 删除连接不再固定打开新 SSH 表单。仅清理被删连接的表单，保留当前服务器/数据库区域及其他活动文档；取消不删除，删除最后一条仍留在当前功能区。
- 连接阶段区分端口拒绝、超时、握手关闭、TLS、认证和数据库不存在等错误；不输出驱动原始错误、SQL 或密码。查询执行阶段继续使用独立的错误处理。

## 用户文件与真实服务

只读取用户指定的 `/Users/liqiang/Downloads/navicat-key.ncx`，不复制源文件或密码进仓库。24 项源配置中有 22 项 MySQL/PostgreSQL，均明确 `SSL=false`；其中 1 项依赖当前尚未映射的 SSH 隧道而跳过，实际预览 21 个直连配置及 21 个可解析密码，3 个 PostgreSQL 库名均正确读取。另 2 项为未支持的 SQLite/SQL Server。

以修复后的同一产品连接实现读取源配置，在临时内存中使用源密码登录并执行 `SELECT 1`：5 项成功（智慧社区-dev、智慧社区-prod、food_safety、rongtong、zhongan-prod），16 项失败，其中 loacal、zhongan 为端口拒绝，其余 14 项为握手关闭。结果见 `output/navicat-fix-selected-services.log`。未写入业务数据、本机正式配置或 Keychain。

无凭据的欢迎包复核中，food_safety 正常返回 MySQL 协议 10；翰鼎新正式服在返回欢迎包前关闭连接，aoqi、住建-dev、teamy-prod-jiwei、返乡登记在读取欢迎包时超时。因此端口可建立 TCP 不能证明数据库握手可用；访问白名单、VPN、代理或服务端状态仍需分别核对，不能把全部失败归结为 TLS 或密码。

## 使用

在修复版中打开“导入与备份”，重新选择同一 NCX，预览后用默认“合并”确认导入，再连接。无需删除原连接或选择替换全部连接。原位修复仅针对仍能精确识别的旧导入身份；手动改动过身份字段的连接需人工核对。此轮未修改已安装应用或用户已有配置。
