# 密码迁移实现与验证

日期：2026-11-11；作者：lq。

## 实现范围

| 来源 | 连接 | 已实现密码格式 | 未覆盖 |
| --- | --- | --- | --- |
| FinalShell JSON 单项/数组 | SSH 名称、地址、端口、账号与可映射分组 | 八字节头部 + Java Random/MD5 派生 DES-ECB/PKCS5 | 加密归档、未知版本格式、私钥文件及私钥口令 |
| Navicat XML（包含内容为 XML 的 `.ncx`） | MySQL/PostgreSQL 名称、地址、端口、账号、初始数据库 | 十六进制 Password 属性或子节点；旧 Blowfish 反馈格式、AES-128-CBC/PKCS7 | 机器绑定 AES-GCM、主密码保护、未兼容容器及来源版本矩阵 |

PuTTY 和 FileZilla 此次不新增密码解码。Navicat 未兼容的 SSH/TLS 设置继续阻断相关连接，不静默改成直连或关闭证书校验；数据库导入后的默认 TLS 策略未改变。FinalShell 私钥认证不把保存密码误认为私钥口令；不读取来源路径指向的外部文件。只读取用户主动选择的文件，不扫描其他应用的凭据库。

## 导入行为

解析与解密在后台完成，预览逐连接显示密码可迁移或认证待补全，并汇总可迁移密码数。报告中不包含口令或密文。确认前不写 SQLite、Keychain 或恢复点。最终确认说明密码数量；取消保留预览。

解码出的密码在临时 Configuration 中与稳定连接 ID 关联，释放时清零；派生材料和解密缓冲也清零。重复连接保留首条配置及密码，防止后条秘密覆盖首条配置。密码超长、无效编码、无效填充、无效 UTF-8 和未知格式保留基础连接并提示补填。此兼容不实现密码猜测、暴力恢复，也不把未知密文当成明文密码。

确认后沿用现有恢复事务：先快照，以随机新引用写入 Keychain，再提交连接配置；配置只保存凭据引用。凭据保存失败时不提交配置，配置提交失败清理新凭据；合并已有连接且本次无密码时沿用现有同身份凭据。旧引用仍可被本机快照用于回滚，不在导入时删除。普通配置导出不包含密码，包含秘密时只能导出为加密备份。

DES、MD5、Blowfish 和固定 AES 参数仅用于兼容来源历史格式；QDS6 本身的备份继续使用 Argon2id + XChaCha20-Poly1305，持久凭据继续保存在系统凭据库。来源旧格式没有认证标签，成功解码不能证明未被修改或服务器口令仍有效；不会为验证而自动连接业务服务器。

## 格式研究与许可

- FinalShell 字段规则参考 [internetathlete/Finalshell-Password-Decrypt](https://github.com/internetathlete/Finalshell-Password-Decrypt/blob/main/finalshell_decoder/decrypt.py)：尤其头部有符号字节、`3680984568597093857 / Random(head[5]).nextInt(127)` 与 Java `nextLong` 符号扩展。未拷贝或运行该外部恢复程序；Rust 和 JDK 测试生成器按格式独立实现，并采用严格填充/UTF-8 失败处理，不回退到损坏明文。
- Navicat 字段规则与已知答案 `15057D7BA390 → 123456` 参考 [HyperSine/how-does-navicat-encrypt-password](https://github.com/HyperSine/how-does-navicat-encrypt-password)，保留原项目作者 HyperSine 的来源归属；不包含其原始程序。这里只实现兼容 v1/v2 字段，不读取其 v3 所需的其他应用系统凭据。
- 标准密码原语使用 RustCrypto `des 0.8.1`、`blowfish 0.9.1`、`aes 0.8.4`、`cbc 0.1.2`、`md-5 0.10.6`、`sha1 0.10.7`。依赖原作者及 MIT/Apache-2.0 等许可原文由现有许可收集脚本保留，不修改第三方源码。

Windows、Navicat 真实用户导出版本矩阵、干净机器安装、Developer ID/公证和用户业务服务器认证均不在本轮已通过范围。
